You have the skill. Here is the other half.

The skill is the client. Cloud2GroundAI is the free app that runs the model it talks to. Four steps, about ten minutes, most of it waiting on a download.

1. Install the free app

The app is free and always will be. It carries the local runtime, the watcher and the bridge folder the skill writes to. It also ships an older free version of the skill — installing the version you bought over it is step 3.

2. Run the setup wizard

Open the app and let the wizard run all five steps. It downloads the model weights (several GB, once), installs the runtime, registers the background watcher, and creates the bridge folder at ~/claude_bridge.

3. Install the skill you bought

Unzip the download from Agensi into your agent's skills folder — for Claude Code and Cowork that is ~/.claude/skills/mlx-delegate/, replacing the free copy the app installed. SKILL.md must sit at the top level of that folder.

The app will not overwrite it. It only replaces a skill older than the one it bundles, and 3.0.0 is newer than the bundled free line.

4. Test the bridge

Back in the app, the wizard's last step is Test the bridge. It writes a real request and waits for the watcher to answer. If it comes back Bridge round-trip OK, everything is wired and you can delegate.

If something is wrong

  • NO-BRIDGE — the skill cannot find the bridge folder. Make sure the app's wizard finished, and that your agent session can reach ~/claude_bridge. In a cloud session, connect that folder to the session.
  • BRIDGE-UNUSABLE — the folder was found but cannot be read or written. The message names the folder and what is missing. This is usually a cloud-synced folder that went read-only, or a sandbox mount without write access.
  • BRIDGE-WARN — sync-conflict duplicates were found next to the protocol files. Delete the duplicates: a stale copy can serve you yesterday's reply.
  • NO-HEARTBEAT — the watcher is not running. Re-run the wizard's "Register background service" step.
